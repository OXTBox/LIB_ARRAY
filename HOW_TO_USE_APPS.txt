HOW TO USE THE APPS
===================
The programs, stacks and helper boards of the LIB_ARRAY: what each one does, which file is the
current one, and what it needs around it. Written 20 Nov 2026 (Claude, for the owner and for
anyone who just downloaded the whole thing). Paths are relative to this "projects" folder.

READ THIS FIRST: FOUR THINGS ALMOST EVERYTHING DEPENDS ON
--------------------------------------------------------
1. KEEP THE FOLDER LAYOUT. Nearly every stack and program finds its libraries by walking UP
   from its own folder until it meets "projects" (the folder holding LIB_LLMOUT, LIB_GAMES ...),
   then looks for the LIB_* folder it needs beside it. Move one project out on its own and it
   will not find its friends. get_everything.sh / .bat and the release zip keep the layout.

2. WHICH IDE OPENS WHAT.
   .livecode   -> LiveCode Community 9.6.3 (64-bit) or OXT-Beyond. Both work.
   .oxtstack   -> OXT-Beyond (Seth Morrow's IDE, the continuation of OpenXTalk / LiveCode 9:
                  github.com/SethMorrowSoftware/OpenXTalk-Beyond). Our copy: V:\APPS\OXT-Beyond-0.2.7
   .livecodescript -> a script-only stack: File > Open Stack in either IDE, or "start using" it
                  from another stack. Most real code lives in these text files; the binary
                  stacks are often only a window that loads them at start.
   .exe        -> Windows standalones built from those stacks. Most are thin LAUNCHERS: they
                  load the current scripts from disk at every start, so editing a script needs
                  no rebuild (the exceptions say so below).

3. THE TWO ENGINES. Vibecode3D (Engine 1, XT) is pure xTalk and draws its own vector lines; it
   even runs with no window. xt3d (Engine 2, xRay) hands the drawing to raylib through a
   LiveCode Builder extension; it needs Windows, a window, and the extension installed at
   C:\xt3d\extension (run xt3D_Raylib_Livecode_Bridge\build.bat once). The same game script
   plays on both. TRAP: xt3D_Raylib_Livecode_Bridge/testbench/vibe_engine_xt3d.livecodescript
   is Engine 1's script, GENERATED by tools/make_vibe_xt3d.py: never edit it by hand.

4. FIXED PLACES OUTSIDE "projects" (Windows side):
   C:\LIB_MCP\            LIB_MCP's token files and livecode_errors.txt (translated script errors)
   C:\xt3d\extension\     the xt3d extension the benches load
   C:\xtsfx\extension\    the LIB_SFX sound extension (after its build.bat)
   Documents\Data\        the Data folder (LIB_DATA): ratings, snapshots, logs, saved games
   %LOCALAPPDATA%\Vibecode3D\logs\   errors from INSTALLED games (the V: install)
   V:\                    "VIBE", a simulated second PC: the Steam-style install lives there
   Ports: every TCP port our programs listen on is in LIB_PORTS/ports.tsv (8766 IDE dev server,
   8767 MCP standalone, 8768 xt3d bench, 8770 games bench, 8188 ComfyUI ...).

THE CLAUDE MAILBOX (how the helper apps talk to the AI)
-------------------------------------------------------
Many apps below write plain text lines for Claude to read. All of it goes through two folders
that are never in git:
   LIB_LLMIN/<project>/        the inbox: notes, feedback, decisions, new files to process
   LIB_LLMOUT/Read/<project>/  the done pile: inbox items Claude has read and acted on
   LIB_LLMOUT/FOR_REVIEW.txt   every file Claude made that waits for the owner's review
   LIB_LLMIN/LIB_DEV/TELL_CLAUDE.txt   one line here ("T" key, Tell Claude button) wakes a
                               waiting Claude session (LIB_DEV/tools/wait_for_tell.sh)
Without Claude these files simply pile up; the apps still work.


=====================================================================
1. PLAYING GAMES
=====================================================================

GAME_Browser  (the short way in to every hand-made game)
   Run:      LIB_DEV/GAME_Browser.exe   (or open LIB_DEV/livecode/GAME_Browser.livecode)
   Does:     lists every game in LIB_GAMES/Vibecode3D_Games with its title, keys, rules,
             levels and script path. Double-click / Return plays it on the engine(s) ticked:
             Vibecode3D, xt3d or both. Right-click: play in one engine, open the script,
             copy its path. Feedback box -> LIB_LLMIN/LIB_GAMES/GAME_NOTES.txt.
   Script:   LIB_DEV/livecode/game_browser.livecodescript (+ game_launch.livecodescript)
   Layout:   LIB_DEV/livecode/GAME_Browser_gui_For_edits.livecode is the owner's layout; the
             build (LIB_DEV/tools/build_game_browser.lc) reads it and never writes to it.
   Needs:    to sit in LIB_DEV; LIB_GAMES beside it; Game_Player.exe for Vibecode3D; the xt3d
             games bench for xt3d (it starts the bench if it is not running).

Game_Player  (one game, one program, one window)
   Run:      LIB_DEV/Game_Player/Game_Player.exe <GameName>   (the GAME_Browser starts it)
   Does:     plays one Vibecode3D game. "..." menu top right: Pause, Reset, Levels, Quit.
             Esc pauses; ` or F2 opens the game-notes box (notes go to GAME_NOTES.txt).
   Scripts:  LIB_DEV/livecode/game_player.livecodescript, launcher_game_player.livecodescript;
             the engine: xt3D_Raylib_Livecode_Bridge/testbench/vibe_engine_xt3d.livecodescript
   Errors:   in the window, and in full in LIB_LLMIN/LIB_DEV/GAME_PLAYER_ERRORS.txt
   Rebuild:  only if the launcher changes: open LIB_DEV/livecode/Game_Player_Launcher.livecode,
             Save as Standalone into LIB_DEV/Game_Player.

Vibecode3D Library  (Steam-style library window for the INSTALLED games)
   Run:      LIB_PUBLIC/launcher/build/Vibecode3D Library/Windows x86-64/Vibecode3D Library.exe
             (stack: LIB_PUBLIC/launcher/Vibecode3D_Launcher.livecode;
              script: LIB_PUBLIC/launcher/vibe_launcher.livecodescript)
   Does:     every installed title, filtered All / Games / Betas / Tools; Play, Show Folder,
             Verify Files. "Vibecode3D Library.exe -game <folder>" plays one game.
   Needs:    an install made by LIB_PUBLIC/install/vibeinstall.py (simulated on V:, layout in
             LIB_PUBLIC/install/LAYOUT.md). It loads the engine from
             vibeapps\common\Vibecode3D Common\Engine\, never from "projects".
   Test:     OXT-BEYOND/tests/t27_vibe_launcher.txt

Comfy Games  (games built by the ComfyUI nodes, with star ratings)
   Run:      LIB_COMFY/Player/ComfyGames.exe   (or LIB_COMFY/Player/ComfyGames.livecode)
   Script:   LIB_COMFY/Player/comfy_games.livecodescript
   Does:     genres left (Pong, Bricks, Waves, Worm, Dodge, Lander, Rocks, Squad, Toss,
             Photon), games middle, stars right (click or keys 1-5, 0 clears); sort Best rated /
             Newest / A-Z; PLAY; "Make a new one" builds a fresh game of the genre in about a
             second WITHOUT ComfyUI; "Open in ComfyUI" when ComfyUI runs on 127.0.0.1:8188.
   Needs:    walks up from itself to the first folder holding games/ (LIB_COMFY/games).
             Stars: Data/Games/ComfyGames/ratings.tsv (Data folder). "Make a new one" needs
             Python 3 (shipped, Comfy Desktop's, or the system's).
   Rebuild:  in OXT-Beyond, recipe in LIB_COMFY/Player/README.md. Tests: t64 (and t53).

ComfyUI nodes  (build games as node graphs, Blueprint style)
   Where:    LIB_COMFY/ComfyUI-Vibecode3D/ (node pack, category Vibecode3D/...)
   Install:  LIB_COMFY/tools/install.sh, then RESTART ComfyUI (Desktop). Workflows to drag in:
             LIB_COMFY/workflows/ (e.g. photon_dangerous.json).
   Does:     chain game parts, set sliders, Queue: the Build Game node writes a playable
             Vibecode3D_Play_<Name>.livecodescript into LIB_COMFY/games. No AI involved.
   Tests:    LIB_COMFY/tests/ (photon_play_test.py ...), OXT-BEYOND t65.

xt3d games bench  (the same games, drawn by raylib)
   Run:      xt3D_Raylib_Livecode_Bridge/standalone/xt3d_Bench_LibMCP/xt3d_Bench_LibMCP.exe
             (stack: .../standalone/xt3d_Bench_LibMCP.livecode;
              script: xt3D_Raylib_Livecode_Bridge/testbench/xt3d_testBench_lib_mcp.livecodescript)
   Does:     Games button = every game in LIB_GAMES/Vibecode3D_Games played in the 3D view;
             Editor button = LIB_EDITOR's example cards (E01..E15).
   Needs:    C:\xt3d\extension (build.bat), LIB_MCP beside it (listens on 8770), LIB_GAMES.
   Plain bench (models, camera, render switches, self-test): .../standalone/xt3d_Bench/xt3d_Bench.exe
             (port 8768; script testbench/xt3d_testbench.livecodescript).

Vibecode3D (the engine's own editor window, the original app)
   Run:      Vibecode3D/standalone/VibeCode3D/Windows x86-64/VibeCode3D.exe
             (same build as Vibecode3D/VibeCode3D_11_15_2026.exe;
              stack Vibecode3D/VIBECODE3D_GUI_v1_LIB_LLM_11152026.livecode)
   Engine source: Vibecode3D/livecode/VIBECODE3D_LIB_MCP_11_11_2026_647PM.livecodescript
   Note:     a standalone cannot save its own stack, so it forgets added game cards at every
             restart: LIB_TEST/INSTALL_ALL_GAMES_Vibecode3D.bat puts them back. The
             GAME_Browser + Game_Player route above avoids this.
   Working notes for the engine: Vibecode3D/LiveCode_Claude_Kit/kit/CLAUDE.md

LIB_TEST  (double-click tests, no AI needed)
   LIB_TEST/README.md: .bat files that start a game on either engine (PLAY_Thrmnlra_xt3d.bat ...).
   Write what you see in LIB_TEST/OBSERVATIONS.txt.

2. LEARNING AND BUILDING
=====================================================================

HOWTO  (92 small steps, 18 topics: "add this handler, this happens")
   Open:     LIB_HOWTO/livecode/HOWTO.oxtstack in OXT-Beyond (a strip at the bottom of the
             screen; each step plays in a Vibecode3D window and an xt3d window above it)
   Script:   LIB_HOWTO/livecode/howto_stack.livecodescript
   Steps:    LIB_HOWTO/topics/<id>_<Title>/step_<n>.txt + step_<n>.livecodescript
   Tools:    LIB_HOWTO/tests/play_step.sh (play one step on the real engine),
             play_step_xt3d.sh, check_calls.py

iGame3D XT  (the 2008 iGame3D editor remade in xTalk on Vibecode3D; a TOOL, not a game)
   Script:   LIB_EDITOR/iGame3D_XT/Vibecode3D_Play_Ig3dEditor.livecodescript (+ Tools/ windows)
   Play:     like a game card (GAME_Browser lists it when installed; README in that folder).
   Needs:    its Tools/ folder; Data folder chosen with Library > Set Data Folder...

Editor example cards  (one editing method per card: E01 Blocks ... E15 Undo)
   Where:    LIB_EDITOR/examples/  (keys in each card's header)
   Play:     the xt3d games bench's Editor button, or headless: LIB_EDITOR/tests/headless.sh

BitEditor  (draw 1-bit glyphs, paint them into a map, set heights: the bitmap-to-3D map editor)
   Open:     LIB_BIT/editor/BitEditor.livecode
   Data:     LIB_BIT/editor/maps/*.cellmap, fonts/, data/tags_default.txt
   Format:   LIB_BIT/editor/CELLMAP_V2.md (five heights a cell). Walk a map in 3D:
             LIB_EDITOR/examples/E13_WalkTheMap.livecodescript. Tests: LIB_BIT/editor/tests/

Unicode Picker  (drag a character into a game window and its procedure builds the thing)
   Open:     LIB_UNICODE/livecode/UnicodePicker.oxtstack (script unicode_picker.livecodescript)
   Use:      next to a game window (HOWTO, GAME_Browser, a Game Player, or the xt3d bench
             while a game plays). Entities = drag to build; Tools / Marks = click to copy.
   Needs:    LIB_UNICODE/REGISTRY.tsv (one meaning per character: check it before using one).

Theme Studio  (one look for every stack)
   Open:     LIB_THEME/Theme_Studio_dev_20261115_133543.oxtstack (newest dev copy)
   Library:  LIB_THEME/livecode/lib_theme.livecodescript; colours in LIB_THEME/themes/*.txt

LIB_SFX  (rfxgen sound effects from 24 numbers; makes .wav files the engine plays)
   Build once: close LiveCode, double-click LIB_SFX/build.bat (puts the extension in C:\xtsfx).
   Library:  LIB_SFX/livecode/lib_sfx.livecodescript (Sfx.Make / Sfx.Play). README has the rest.

4. HELPER BOARDS FOR THE DEVELOPER (LIB_DEV)
=====================================================================

Project Map  (the whole project on one zoomable board: where we are, where we go, what blocks)
   Open:     LIB_DEV/ProjectMap/ProjectMap.oxtstack in OXT-Beyond
   Script:   LIB_DEV/livecode/board_canvas.livecodescript (shared with On Git or Not)
   Data:     LIB_DEV/ProjectMap/board.txt (hand-kept, any text editor, format at its top) +
             map_data.txt (written by tools/make_map.py: do not edit) + positions.txt
   Keys:     wheel zoom, drag pan, F fit, B blockers only, R rebuild, T tell Claude, 0 = 100%
   Writes:   LIB_LLMIN/LIB_DEV/MAP_NOTES.txt (blocker notes), REVIEW_STATE.txt,
             REVIEW_FEEDBACK.txt, BOARD_COMMENTS.txt
   Needs:    Python 3 for R (rebuild); LIB_MENU for its menus. README: LIB_DEV/ProjectMap/README.md

Priority Tube  (everything to do as bubbles in a tube: the top is done first)
   Open:     LIB_DEV/PriorityTube/PriorityTube.oxtstack
   Script:   LIB_DEV/livecode/priority_tube.livecodescript
   Data:     bubbles from the boards' comments + the Project Map's next steps
             (tools/tube_items.py); YOUR order is saved in LIB_LLMIN/LIB_DEV/PRIORITY_ORDER.txt
             and Claude works from the top. Sizes: claude_sizes.txt.
   Use:      drag a bubble, or arrows (Shift = top/bottom); right-click for its menu; R reload.
   Needs:    LIB_MENU two folders above. Test: OXT-BEYOND/tests/t40_priority_tube.txt

On Git or Not  (every folder: on git, or not, and why)
   Open:     LIB_DEV/OnGitOrNot/OnGitOrNot.oxtstack
   Data:     map_data.txt from tools/git_map.py. Loose-file decisions (Commit / Ignore /
             Delete / Leave) -> LIB_LLMIN/LIB_DEV/GIT_DECISIONS.txt; Claude carries them out.

Status Browser  (every file the AI made for review, with its notes; feedback goes back)
   Run:      LIB_DEV/Status_Browser_Launcher.exe (opens the current Status_Browser.livecode)
             or LIB_DEV/Status_Browser.livecode
   Script:   LIB_DEV/livecode/status_browser.livecodescript
   Layout:   LIB_DEV/livecode/Status_Browser_gui_For_edits.livecode (owner's; build reads it)
   Reads:    LIB_LLMOUT/FOR_REVIEW.txt. Writes REVIEW_STATE.txt / REVIEW_FEEDBACK.txt.

Ports  (who listens on which port right now; close an older duplicate)
   Open:     LIB_PORTS/Ports.oxtstack (script livecode/ports_window.livecodescript)
   Registry: LIB_PORTS/ports.tsv. Command line: python3 -I LIB_PORTS/tools/ports_check.py live

5. TOOLS FOR AI AND AUTOMATION (no window, or a window for the AI)
=====================================================================

LIB_MCP  (lets Claude Code, a local model or any script drive a running LiveCode)
   In the IDE: start using stack "LIB_MCP/livecode/lib_mcp.livecodescript"  (port 8766)
   Standalone: LIB_MCP/standalone/xt3d_MCP/Windows x86-64/xt3d_MCP.exe      (port 8767)
   Terminal:   LIB_MCP/tools/lcmcp ping | run | compile | errors | harvest
   Writes:     C:\LIB_MCP (tokens, livecode_errors.txt). MCP server for LM Studio / Claude
               Desktop: LIB_MCP/python/lib_mcp/mcp_server.py
OXT-Beyond MCP bridge (in OXT-Beyond: Development > Plugins > xTalk MCP Bridge): how Claude
   reads, changes, runs and saves the stacks open there; it asks before every run and save.

Headless tests (play stacks with no window)
   OXT-BEYOND/tests/oxt_headless.py runs the tNN_*.txt tests on OXT-Beyond's engine
   (RESULTS_beyond.txt); LIB_BIT/editor/tests/run_headless.py on the 9.6.3 server
   (LIB_BIN/livecode-server). LIB_GAMES/tools/engine_play.sh plays a game on the real engine
   and takes a picture. OXT-BEYOND is a local folder (not on GitHub).

XTJSON  (stacks <-> JSON: every card, control, property and script as plain files)
   Harvest:  LIB_XTJSON/livecode/LCHarvest2_livecodescript.txt (or: LIB_MCP/tools/lcmcp harvest X.livecode)
   Rebuild:  LIB_XTJSON/livecode/LIB_XTJSON.livecodescript. Harvests land in XTJSON/ (local).
   Inbox:    drop stacks in LIB_LLMIN/LIB_XTJSON (make the folder if it is not there).

LIB_BUILD  (copy everything the benches and the Vibecode3D standalone need to another PC)
   Open LIB_BUILD/collector.livecodescript, press Collect, pick an empty folder (list: parts.txt).

Spark  (a small local model in LM Studio that drafts; Claude checks)
   LIB_SPARK/ (runs and what they taught); the model itself is not included: bring your own.

LIB_MOCAP  (video -> motion capture -> animated stick figures for both engines)
   Drop captures (.bvh, MoCapAnything *_skeleton.glb) in LIB_LLMIN/LIB_MOCAP (make it), then
   python3 LIB_MOCAP/tools/mocap_lib.py process. Clip library: LIB_BVH. Needs MoCapAnything
   for new captures (not included).

Batch files (.bat) and small utilities: one home, LIB_BAT (one README row each), e.g.
   LIB_BAT/get_everything.bat (every OXTBox project in one folder), kill_explorer_exes.bat.
